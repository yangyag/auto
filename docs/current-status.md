# auto 현재 상태 정리

기준 시각: 2026-04-14 10:23:16 KST

## 1. 최근 반영된 변경

### `grid.txt` 핫리로드
- 실행 중 봇이 매 루프마다 `grid.txt`의 외부 수정 여부를 확인한다.
- 파일이 바뀌면 `GridState.reload_if_changed()`로 즉시 재로드하고, 다음 루프부터 새 상태를 사용한다.
- 따라서 현재는 `grid.txt` 수정 후 봇 재시작이 필수는 아니다.

### 초기 그리드 생성 수량 기준 변경
- `config/settings.py`에 `GRID_FIRST_BUY_AMOUNT_KRW = 200000`이 추가되었다.
- `core/grid_builder.py::build_cash_only_grid()`는 총예산 균등 분배가 아니라, 첫 슬롯 `buy_price` 기준으로 `20만원어치` 살 수 있는 BTC 수량을 계산해 기본 그리드를 만든다.
- `python3 main.py init-grid`도 `--total-budget`이 아니라 `--first-buy-amount` 기준으로 동작한다.

### 현재 운영용 수동 그리드 재작성
- 현재 `grid.txt`는 수동 편집 기준으로 `20슬롯` 구조다.
- 1번 `buy_price`는 `127,886,000 KRW`, 20번 `buy_price`는 `91,623,000 KRW`다.
- 모든 슬롯은 빈 슬롯 상태이며 `held_qty = 0`, `테이블 총재고 : 0`이다.
- `planned_qty`는 각 슬롯의 `buy_price` 기준 약 `200,000 KRW`어치가 되도록 개별 계산되어 슬롯마다 다르다.

### 날짜별 로그 + 백그라운드 스크립트
- 운영 로그는 루트 `trading.log` 단일 파일이 아니라 `logs/trading-YYYY-MM-DD.log`에 날짜별로 남는다.
- `run.sh` / `stop.sh`를 추가해 `nohup python3 main.py`를 감싸고 `.auto-trading.pid`로 PID를 관리한다.
- 루트 `trading.log`는 레거시 파일이었고 현재 운영 기준에서는 제거했다.

### 기타
- `python-dotenv`가 없어도 프로젝트 루트 `.env`를 읽을 수 있도록 `config/settings.py`에 fallback 로더가 추가되었다.

## 4. 운영 시 주의할 점

### 4-1. 로그에서 테스트와 실운용을 구분해야 함
- `python3 -m unittest discover -s tests -v` 실행 시에도 로거가 활성화되어 같은 날짜 로그 파일에 기록이 남을 수 있다.
- 실운용 실행은 로거 이름이 `__main__`으로 찍히고, 테스트에서 `import main` 경로를 타면 `main` 또는 테스트 모듈 이름으로 찍힌다.
- 예를 들어 `심볼: KRW-BTC | 전체 슬롯: 1 | ... 총배정금액: 400 KRW` 같은 줄은 테스트용 임시 grid 로그다.

### 4-2. 교차 전략이므로 시작 직후 즉시 매수하지 않음
- 첫 가격 스냅샷에서는 주문을 만들지 않는다.
- 이후 `이전 가격 > buy_price >= 현재 가격`일 때만 매수 주문이 생긴다.
- 따라서 현재가가 이미 두 슬롯 사이에 있어도, 실제로 한 번 위에서 아래로 통과하지 않으면 주문이 없다.

### 4-3. `grid.txt` 수동 편집은 여전히 주의가 필요함
- 현재는 모든 슬롯이 빈 슬롯이라 orphan 보유분 문제는 없다.
- 다만 추후 보유 슬롯을 수동으로 넣을 때는 `held_qty`와 `planned_qty`를 함께 맞춰야 한다.
- 체결 반영은 주문 상태가 `done`일 때만 이뤄지며, `wait`/`watch`는 pending으로 남는다.

### 4-4. 백그라운드 운영은 스크립트 기준으로 본다
- `./run.sh`는 중복 실행을 막고 `.auto-trading.pid`를 갱신한다.
- `./stop.sh`는 같은 PID만 종료한다.
- 실제 살아 있는 프로세스와 PID 파일이 어긋난 경우에는 `ps` 기준으로 최종 확인한다.
