그리드 슬롯 수

(1) GRID_COUNT를 직접 지정

N = GN
[식 1]
I = N − 1
[식 2]

(2) GRID_STEP_PCT를 지정

Δlog = ln(U / L)
[식 3]
δlog = ln(1 + pstep / 100)
[식 4]
Iraw = Δlogδlog
[식 5]

후보 구간 수:

𝓘cand = { ⌊Iraw⌋, ⌈Iraw⌉ }
[식 6]

각 후보의 오차:

E(j) = | Δlogj − δlog |
[식 7]

𝓘cand 안에서 E(j)가 가장 작은 후보를 I로 선택한다. 오차가 같으면 더 큰 I를 선택한다.

N = I + 1
[식 8]
🔢 워크드 예시 (가상 수치) · pstep = 1%, U = 1,530, L = 1,430

※ 계산 흐름 설명용 예시다. 실제 라이브 운영값은 GRID_STEP_PCT = 0.2, MIN_BUY_PRICE = 1450, MAX_BUY_PRICE = 1500이다.

Δlog = ln(1,530 / 1,430) = ln(1.06993) ≈ 0.06759

δlog = ln(1 + 0.01) ≈ 0.00995

Iraw ≈ 0.06759 / 0.00995 ≈ 6.79

𝓘cand = { 6, 7 }

E(6) = | 0.06759 / 6 − 0.00995 | ≈ 0.00132

E(7) = | 0.06759 / 7 − 0.00995 | ≈ 0.00029

→ I = 7, N = 8

매수 가격 사다리

상단에서 하단으로 내려가는 로그 간격 사다리다.

ℓ = ln(U / L)N − 1
[식 9]
g = eℓ
[식 10]
B0 = U
[식 11]
Bi = Fnorm( Ugi ),   0 < i < N − 1
[식 12]
BN−1 = L
[식 13]
⚠ 중복 호가 실패

호가 단위 적용 후 Bi가 중복되면 그리드 생성은 실패한다.

유도 메모 — 왜 로그 간격인가

ℓ는 인접한 두 buy 가격 사이의 로그 거리다. Bi+1 / Bi = 1/g = e−ℓ로 일정하므로, 호가가 작은 하단도 같은 비율로 촘촘해진다. 결과적으로 각 슬롯의 매수 후 다음 슬롯까지의 하락폭(%)이 일정해진다.

예산 가중치

슬롯 인덱스는 상단이 0, 하단이 N − 1이다.

bi = min( ⌊ 3iN − 1 ⌋, 2 )
[식 19]
wi = 0.7bi = 0 1.0bi = 1 1.3bi = 2
[식 20]
W = Σi=0N−1 wi
[식 21]

슬롯별 예산 배분:

Bslot, i = Btotal · wiW
[식 22]
Qi = Fstep( Bslot, iBi, 0.00000001 (기초자산 단위, cfg.SYMBOL) )
[식 23]
🔢 워크드 예시 · N = 10

bi = min(⌊3i/9⌋, 2) → 인덱스 0..9에 대해: 0, 0, 0, 1, 1, 1, 2, 2, 2, 2

가중치: 상위 3슬롯 0.7, 중간 3슬롯 1.0, 하위 4슬롯 1.3

W = 3 × 0.7 + 3 × 1.0 + 4 × 1.3 = 2.1 + 3.0 + 5.2 = 10.3

하단(i = 9)의 슬롯 예산 비율 = 1.3 / 10.3 ≈ 12.6% — 더 싼 가격대에 더 많은 KRW를 배정.

현재 재고 원가와 총 배정 금액

현재 보유 재고 원가:

Cinventory = Σi ∈ ℋ Bi Hi
[식 24]

총 배정 금액:

Ballocated = Σi ∈ ℋ Bi Hi + Σi ∈ ℰ Bi Qi
[식 25]

여기서 ℋ는 holding 슬롯 집합, ℰ는 empty 슬롯 집합이다.

매수 교차 조건

하락 매수 후보:

Pprev > Bi ≥ P
[식 26]

추가 조건

  • 슬롯 i가 empty 상태다.
  • 슬롯 i에 pending 주문이 없다.
  • 슬롯 i가 active buy window 안에 있다.
  • inventory target gate를 통과한다.
  • breakout guard가 비활성이다.

  • 슬롯 i에 pending 주문이 없다.
  • 슬롯 i가 active buy window 안에 있다.

기준 가격은 Pprev다.

정렬 기준

𝓐 = firstn≤(𝓑≤) ∪ firstn>(𝓑>)

[식 33]

Inventory Target Gate

운영 예산 분모:

Bop = BmaxopBmaxop > 0 BallocatedBmaxop ≤ 0
[식 35]

현재 재고 비율은 같은 평가 사이클에서 이미 승인된 매수 후보까지 반영한 projected inventory 기준이다.

qcurrent = CprojectedBop
[식 36]

로그 밴드 위치:

zraw = ln(P) − ln(L)ln(U) − ln(L)
[식 37]
z = clamp(zraw, 0, 1)
[식 38]

목표 재고 비율:

qtarget(z) = qmin + (qmax − qmin)(1 − z)γ
[식 39]
qtarget(z) = clamp(qtarget(z), qmin, qmax)
[식 40]

통과 조건:

θ = max(qtarget(z) − ε, 0)
[식 41]
gpass = ( qcurrent < θ )
[식 42]
해석 메모 — z 와 qtarget의 관계

z는 로그 가격대 안에서 현재가의 위치다. z = 0 은 하단(L), z = 1 은 상단(U).

(1 − z)γ 항이 있으므로 가격이 낮을수록 qtarget은 qmax에 가까워지고, 높을수록 qmin에 가까워진다. → "쌀 때 더 많이 들고, 비쌀 때 줄여라."

Age TP 압축

보유 시간:

a = tnowUtc − tfilledUtc
[식 47]

k 압축량:

d(a) = 1.0a ≥ 7 days 0.548 hours ≤ a < 7 days 0.0a < 48 hours
[식 48]

유효 k:

keff = max( kbase − d(a), kfloor )
[식 49]

압축 매도 가격:

gbase = ln( Si / Bi )
[식 50]
gcompressed = gbase · keffkbase
[식 51]
Si′ = Fnorm( Bi · egcompressed )
[식 52]

최종 매도 가격:

Sieff = Si′Bi < Si′ < Si Siotherwise
[식 53]
🔢 워크드 예시 (가상 수치) · kbase = 2.0, kfloor = 1.0, a = 72h

※ 아래 가격·배수는 계산 흐름 설명용 가상 수치다. 실제 라이브 운영값은 TP_K_BASE = 3.2, TP_K_FLOOR = 3.0이며 마켓 스케일도 다르다.

a = 72h → 48h ≤ a < 7d 이므로 d(a) = 0.5

keff = max(2.0 − 0.5, 1.0) = 1.5

예: Bi = 1,450, Si = 1,479

gbase = ln(1,479 / 1,450) ≈ 0.01980

gcompressed = 0.01980 × (1.5 / 2.0) ≈ 0.01485

e0.01485 ≈ 1.01496 → 압축 매도가 ≈ 1,471.7 (정규화 전)

Bi < 압축가 < Si 이므로 Sieff = 압축 매도가

손절(Stop Loss) 판정 수식

그리드 하한(L) 아래로 시세가 추가 이탈할 때 단계별로 청산하는 자동 손절 서브시스템이다. 구현은 app/strategy/stop_loss.py, 파라미터 검증은 app/core/grid_properties.py의 validate_stop_loss_config(), 운영값은 grid.properties를 기준으로 한다. 여기서 L = MIN_BUY_PRICE(최하단 슬롯 매수가), U = MAX_BUY_PRICE(최상단 슬롯 매수가)다.

손절 임계가 산출

손절 모드는 STOP_LOSS_MODE로 선택하며 band_multiple(기본/권장), fixed_pct, off 세 가지다.

band_multiple 모드 — 밴드 폭(하락률)에 배수 kband(STOP_LOSS_BAND_MULTIPLE)를 곱한 단일 임계가를 사용한다. 레벨에 무관하게 동일한 값이다.

Tband = L · ( 1 − kband ( 1 − LU ) )
[식 64]

fixed_pct 모드 — 레벨별 하락 백분율 pLn(STOP_LOSS_Ln_PCT)에 따라 레벨별 임계가를 산출한다.

TLn = L · ( 1 − pLn100 ),   n ∈ { 0, 1, 2 }
[식 65]

레벨 분기

현재가 P가 TL0 이상이면 미발동이다. 그 아래로 떨어지면 임계가 비교로 레벨을 분기한다.

level = 미발동P ≥ TL0 2P < TL2 1TL2 ≤ P < TL1 0TL1 ≤ P < TL0
[식 66]
⚠ band_multiple 모드의 L2 직행

식 64의 Tband는 레벨과 무관한 단일값이므로 TL0 = TL1 = TL2 = Tband로 수렴한다. 따라서 시세가 단일 밴드 임계가 아래로 이탈하는 순간, 식 66에서 P < TL2 분기가 먼저 성립해 곧바로 L2(전량 시장가 청산)로 직행한다 (L0/L1 중간 단계 없음).

연속 종가 컨펌

레벨이 분기되어도 즉시 청산하지 않고, STOP_LOSS_CANDLE_UNIT(분) 단위 캔들의 연속 종가가 임계가 아래에서 마감되는지로 컨펌한다. 레벨별 필요 연속 종가 수는 nLn(STOP_LOSS_Ln_CONSECUTIVE_CLOSES)다.

carm = ⋀j=1nLn ( Cj < TLn )
[식 67]
  • STOP_LOSS_L0_CONSECUTIVE_CLOSES = 4 (검증: ≥ 2)
  • STOP_LOSS_L1_CONSECUTIVE_CLOSES = 4 (검증: ≥ 2)
  • STOP_LOSS_L2_CONSECUTIVE_CLOSES = 2 (검증: ≥ 1)

carm = true일 때 해당 레벨이 ARM(무장)되며, armed_at(최초 무장 시각)이 기록·유지된다.

레벨별 청산 동작

  • L0: 신규 매수만 차단(no-op). 보유 재고는 청산하지 않는다.
  • L1: 보유 슬롯을 임계가(TL1) 기준 지정가 부분 청산한다. 청산 비율 rL1 = STOP_LOSS_L1_LIQUIDATE_RATIO = 0.5.
qsell, i = Hi · rL1,   rL1 = 0.5
[식 68]
  • L2: 보유 슬롯 전량 시장가 청산(rL2 = 1). 청산 후 재시작 잠금 시간 τlock(STOP_LOSS_RESTART_LOCKOUT_HOURS) 동안 봇 재가동이 잠긴다.
τlock = 24 hours
[식 69]
🚫 라이브 운영값

현재 라이브는 STOP_LOSS_MODE = off로 운용 중이다 (그리드 폭이 MIN_BUY_PRICE = 1450~MAX_BUY_PRICE = 1500 ≈ 3.45%로 좁아 band_multiple을 적용할 수 없기 때문). 참고로 band_multiple은 validate_stop_loss_config()에서 1.0~2.0 범위로 강제되며, 식 64의 Tband가 0.5L < Tband < 0.9L 구간에 들어야 정상 운영 구간 침범/하한 50% 초과 검증을 통과한다 (코드 기본값은 app/config/settings.py의 1.5). 좁은 그리드에서는 이 두 검증을 동시에 만족하는 배수가 존재하지 않아(대략 그리드 폭 5.26% 이상이어야 성립) band_multiple 적용이 불가하다.
