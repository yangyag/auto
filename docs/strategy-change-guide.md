# 기존 전략 vs 현재 전략

이 문서는 운영자가 "예전 판과 지금 판이 무엇이 달라졌는가"를 빠르게 이해하기 위한 설명서다.

설계 문서가 아니라 운영 문서에 가깝다.
즉, 코드 구조보다 "언제 사고, 언제 덜 사고, 왜 수익과 자본 점유가 달라지는가"에 집중한다.

현재 전략 수치는 `2026-04-20` 에 적용한 새 `grid.properties` 기준 예시다.
나중에 `grid.properties` 를 다시 바꾸면 숫자 자체는 달라질 수 있다.

## 한눈에 보기

| 항목 | 예전 운영 기준 | 현재 운영 기준 |
|------|----------------|----------------|
| 그리드 범위 예시 | `91,623,000 ~ 127,886,000` | `98,000,000 ~ 121,000,000` |
| 슬롯 수 | `122` | `96` |
| 슬롯 예산 | 거의 균등, 슬롯당 약 `50,000 KRW` | 상단 약 `17,500 KRW`, 중단 약 `25,000 KRW`, 하단 약 `32,500 KRW` |
| 매도 기준 | 레거시 `SELL_PERCENT=3.2` 고정형 | 기본 `TP_MODEL=k`, `TP_K_BASE=10.5`, `TP_K_FLOOR=8.0` |
| 상승 추격 매수 | 포함 가능, 운영자가 체감하기에 더 공격적 | 기본 `OFF` |
| 하락 매수 범위 | 하락 중 교차한 empty 슬롯을 넓게 매수 | 활성 윈도우 안의 근접 슬롯 위주 매수 |
| 재고 제어 | 약함 | `q_target(z)` inventory gate 적용 |
| 추세장 대응 | 약함 | 브레이크아웃 가드로 신규 매수 차단 |
| 주문 제출 | 실주문 중심 | `orders/chance` -> `orders/test` -> 실주문 |

## 공통으로 유지되는 것

- 둘 다 업비트 `KRW-BTC` + PostgreSQL 상태 저장소를 기준으로 한다.
- 둘 다 절대 가격이 아니라 poll 구간의 가격 교차를 본다.
- 하락 교차 매수는 기본적으로 지정가 주문이다.
- 주문이 접수됐다고 바로 상태를 바꾸지 않고, 업비트 재조회 결과가 `done`일 때만 PostgreSQL 그리드 상태를 갱신한다.

즉, 전략의 뼈대는 여전히 "그리드 + 교차 판정 + 체결 확인 후 상태 반영"이다.
달라진 것은 주로 "얼마나 공격적으로 매수하느냐"와 "익절 목표를 어떻게 잡느냐"다.

## 예전 전략

예전 운영판은 운영자가 체감하기에 아래 성격에 더 가까웠다.

- 슬롯 수가 많았다.
- 슬롯당 예산이 거의 같았다.
- `3.2%` 같은 고정 percent TP를 기준으로 매도했다.
- 가격이 하락하면서 여러 슬롯을 한 poll 안에 통과하면, 그 슬롯들을 비교적 넓게 다 받는 쪽이었다.
- 상승 시 단일 슬롯 상향 돌파 예산매수 경로도 있어, 반등 초입에서 따라붙는 느낌이 더 있었다.

운영 감각으로 보면 이 판은 "잘 맞는 횡보장에서는 회전이 빠르고 수익이 크게 날 수 있지만, 추세 하락에서는 재고가 빨리 쌓이는 쪽"이었다.

## 현재 전략

현재 운영판은 새로 [grid.properties](../grid.properties) 를 적용해 다시 만든 뒤 아래 성격으로 바뀌었다.

- 슬롯 수를 `96`으로 줄였다.
- 상단 슬롯은 가볍게, 하단 슬롯은 더 세게 사도록 예산을 비대칭 배분한다.
- 기본 익절은 레거시 percent가 아니라 `k` 기반 TP다.
- `k` 기반 holding 슬롯은 오래 묶이면 age-aware `effective_sell_price` 가 조금 더 낮아질 수 있다.
- 상승 1칸 돌파 추격 매수는 기본적으로 꺼져 있다.
- 하락 매수도 아무 슬롯이나 다 받지 않고, [strategy/grid_strategy.py](../strategy/grid_strategy.py) 의 활성 윈도우와 inventory gate를 먼저 통과해야 한다.
- 최근 완료된 15분 종가가 밴드 밖에서 4개 연속 나오면 [main.py](../main.py) 의 브레이크아웃 가드가 신규 매수를 막는다.
- 주문 제출 전에는 [exchange/crypto.py](../exchange/crypto.py) 경로에서 `orders/chance`, `orders/test`를 먼저 확인한다.

운영 감각으로 보면 이 판은 "수익 최대화보다, 자본이 너무 빨리 묶이지 않게 하면서 더 오래 버티는 쪽"이다.

## 무엇이 실제로 달라졌는가

### 1. 하락장에서 덜 빨리 산다

예전 판은 하락 구간에서 교차한 슬롯들을 넓게 받는 편이었다.
현재 판은 같은 하락이라도 다음 조건을 동시에 본다.

- 활성 윈도우 안의 근접 슬롯인가
- 이미 재고가 충분한 상태는 아닌가
- 브레이크아웃 가드가 켜진 구간은 아닌가

즉 지금은 "조건 닿으면 바로 산다"보다 "지금도 사는 게 맞는가"를 한 번 더 보는 구조다.

### 2. 아래로 갈수록 더 많이 산다

현재 [core/grid_properties.py](../core/grid_properties.py) 의 `grid.properties` 경로는 총예산 `BUY_AMOUNT_KRW * GRID_COUNT` 를 아래처럼 나눈다.

- 상단 1/3: `0.7x`
- 중단 1/3: `1.0x`
- 하단 1/3: `1.3x`

그래서 지금 판은 위쪽에서는 얕게 진입하고, 더 아래에서는 같은 슬롯 수라도 더 크게 진입한다.

### 3. 익절 기준이 고정 percent에서 `k` 기반으로 바뀌었다

예전 판은 "사고 나서 몇 퍼센트 오르면 판다"에 가까웠다.
현재 판은 "로그 간격 기준으로 몇 칸 반등하면 파는가"에 가깝다.

운영자가 느끼는 차이는 이렇다.

- percent TP는 직관적이다.
- `k` TP는 그리드 간격이 바뀌어도 전략 성격이 덜 흔들린다.

즉 현재 판은 `GRID_COUNT` 나 범위를 바꿔도 익절 구조가 덜 무너지는 쪽을 노린다.

### 4. 상승 추격 매수는 기본 OFF다

예전 운영 감각에서는 "살짝 반등하면 한 칸 추격해서 사는" 동작이 섞여 있었다.
현재는 이 경로가 기본적으로 꺼져 있다.

따라서 지금 판은 반등장에서 예전보다 덜 공격적이다.

### 5. 추세장에서는 신규 매수를 멈춘다

현재는 최근 완료된 15분 종가가 밴드 밖에 연속으로 남아 있으면 신규 매수를 막는다.
이미 가진 물량의 매도는 계속 허용한다.

이건 수익 확대용 기능이 아니라, "계속 떨어지는 장에서 멍청하게 더 사지 않기 위한 보호장치"에 가깝다.

## 같은 가격 경로에서 대략 어떤 차이가 나는가

아래 숫자는 운영 설명용 거친 비교다.

- 시작 재고: `0 BTC`
- 수수료/슬리피지/부분체결 제외
- 예전 판: `122` 슬롯, 총예산 약 `6,099,936 KRW`, 균등 슬롯, `3.2%` TP
- 현재 판: `96` 슬롯, 총예산 약 `2,399,950 KRW`, 하단 가중, `k=10.5 / floor=8.0`

즉 절대 손익은 공정 비교가 아니다.
예전 판은 애초에 더 많은 자본을 태우는 구조이기 때문이다.
그래도 운영 감각을 잡는 데는 도움이 된다.

| 시나리오 | 가격 경로 | 예전 판 | 현재 판 |
|----------|-----------|---------|---------|
| 얕은 눌림 후 복귀 | `111.957M -> 108M -> 105M -> 109M -> 113.5M` | 총손익 약 `34,055 KRW`, 최대 재고투입 약 `1,149,989 KRW` | 총손익 약 `16,084 KRW`, 최대 재고투입 약 `699,986 KRW` |
| 중간급 하락 후 반등 | `111.957M -> 106M -> 102M -> 99.5M -> 104.5M -> 110.5M` | 총손익 약 `50,964 KRW`, 최대 재고투입 약 `2,149,978 KRW` | 총손익 약 `28,554 KRW`, 최대 재고투입 약 `1,512,473 KRW` |
| 하단 근접 후 강한 V반등 | `111.957M -> 104M -> 100M -> 98.2M -> 103M -> 109M -> 116M` | 실현손익 약 `75,188 KRW`, 최대 재고투입 약 `2,349,976 KRW` | 실현손익 약 `40,245 KRW`, 최대 재고투입 약 `1,707,470 KRW` |

첫 두 시나리오의 `총손익` 은 마지막 가격 기준 평가손익이 일부 포함된 값이다.
세 번째 시나리오는 최종적으로 보유 슬롯이 모두 정리돼 실현손익만 남은 케이스다.

운영자 기준 해석은 간단하다.

- 예전 판은 반등이 잘 나오면 더 많이 번다.
- 현재 판은 같은 상황에서 덜 벌 가능성이 높다.
- 대신 현재 판은 자본이 덜 묶이고, 추세 하락에서 덜 망가진다.

즉 현재 판은 "공격적으로 먹는 전략"보다는 "덜 무너지고 오래 반복하는 전략"에 가깝다.

## 언제 예전 판이 더 유리하고, 언제 현재 판이 더 유리한가

예전 판이 더 유리한 경우:

- 넓은 박스권 횡보가 오래 이어질 때
- 하락 뒤 반등이 강하고 빨리 나올 때
- 운영자가 더 큰 재고와 더 큰 자본 점유를 감당할 수 있을 때

현재 판이 더 유리한 경우:

- 하락 추세가 길어질 수 있을 때
- 계좌가 너무 빨리 묶이는 것을 줄이고 싶을 때
- 운영 자본이 예전보다 작거나, 회전보다 생존성이 더 중요할 때

## 새 판을 다시 만들 때만 바뀌는 것

아래 항목은 코드를 올리기만 해서는 완전히 반영되지 않는다.
실제로 새 그리드를 다시 생성해야 적용된다.

- 슬롯 수 변화
- 하단 가중 예산 배분
- `k` 기반 TP 생성
- 새 범위(`MIN_BUY_PRICE`, `MAX_BUY_PRICE`)

반대로 아래 항목은 코드만 올려도 운영 동작에 바로 반영될 수 있다.

- inventory-target gate
- 활성 윈도우
- 브레이크아웃 가드
- 상승 추격 매수 OFF
- 업비트 주문 프리플라이트

## 운영자가 기억할 것

- 지금 판은 예전 판보다 "덜 공격적"이다.
- 그 대신 자본이 더 천천히 묶이고, 추세장 보호가 더 강하다.
- 횡보장 수익만 보면 예전 판이 더 좋아 보일 수 있다.
- 하지만 운영 안정성과 생존성까지 같이 보면 현재 판이 더 보수적이고 관리하기 쉽다.
